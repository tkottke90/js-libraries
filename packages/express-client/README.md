# Express Client Library

## What Problem Does This Solve?

When building full-stack JavaScript applications, keeping your frontend and backend in sync is challenging:

**Without Express Client:**
```typescript
// frontend/src/api.ts - Manually maintained
const response = await fetch('http://localhost:3000/api/v1/user/', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'John', email: 'john@example.com' })
});
const user = await response.json(); // No type safety!
```

**With Express Client:**
```typescript
// Type-safe, validated, and synchronized with your backend
import { createUser } from 'my-app-client';

const user = await createUser({ name: 'John', email: 'john@example.com' });
// Full TypeScript support and runtime validation!
```

This library provides a way to define your API contract in a single place and generate type-safe client code from it. When the server's API changes, TypeScript will catch breaking changes at compile time, and runtime validation ensures data integrity.

## Requirements

- **Node.js**: 22.x or higher
- **TypeScript**: 5 or higher (if using TypeScript)
- **Zod**: 4.x (optional, for validation)
- Works with any Express.js version

## Quick Start

1. **Install the library in your backend:**
   ```bash
   cd backend
   npm install @tkottke90/express-client
   ```

2. **Run the setup script:**
   ```bash
   npx express-client-init
   ```

3. **Follow the interactive prompts:**
   - Choose your build type (TypeScript or ESBuild)
   - Select where to create the client directory (default: `client/`)
   - Confirm the setup

4. **Install dependencies:**
   ```bash
   cd client
   npm install
   ```

5. **Define your API methods** in `client/src/index.ts` and build:
   ```bash
   npm run build
   ```

6. **Install in your frontend:**
   ```bash
   cd ../../frontend
   npm install file:../backend/client
   ```
   
   > **Note:** This installs the client as a local dependency. When you rebuild the client, run `npm install file:../backend/client --force` to update. For production, consider publishing to npm or using alternatives like `npm link` for development.

## Setup

### Automated Setup (Recommended)

The easiest way to get started is to use the interactive setup script:

```bash
npx express-client-init
```

This will guide you through the setup process and create:
- A `client/` directory (or your chosen location)
- A `package.json` configured for your project
- A `tsconfig.json` with appropriate settings
- A `build.mjs` script (if you choose ESBuild)
- A `src/` directory with an example `index.ts` file

**Build Type Options:**
- **TypeScript Compiler (tsc)**: Standard compilation, simple setup, good for smaller projects
- **ESBuild (Recommended)**: Faster builds with bundling, better for larger projects

### Manual Setup

If you prefer to set up the client directory manually, follow these steps:

1. Create a `client` directory
2. Create a `tsconfig.json` file for your client
3. Create a package.json file for your client so that you can install it with npm
4. Add a build script to your package.json file that compiles the client code and outputs it to a `dist` directory

## Usage

To use this library, you install it as a dependency in your API.

```bash
cd backend
npm install @tkottke90/express-client
```

This package exposes a `createClientMethod` function that you can use to define the client methods:

```typescript
// backend/client/src/index.ts
import { createClientMethod } from '@tkottke90/express-client';

export const createUser = createClientMethod(
  '/api/v1/user/',
  { method: 'GET' }
);
```

After defining your methods, build the client:

```bash
cd client
npm run build
```

This will generate a client method that can be used to call the API endpoint. The generated method will have the same signature as the server method, so you can use it in your client code without having to worry about the underlying API contract.

```typescript
// frontend/src/app.ts
import { createUser } from '<app-name>-client';

const userResponse: Response = await createUser({ name: 'John Doe' });
```

### Input/Output Types

On it's own this library is a fancy wrapper around `fetch`.  This provides the first benefit of having a pre-configured URL/Method to call instead of having to maintain that information in the client code separate from the API definition.

With the inclusion of `zod` schemas, you can make your client methods even more powerful. By defining the input and output schemas for your API endpoints, you can ensure that the data being sent and received is always in the correct format. This can help to catch errors early and make it easier to debug issues when they arise.

#### Input Validation

Going back to our user creation example, we can make sure that the input data is in the correct format by defining a `zod` schema for the user data:

```typescript
// backend/client/src/index.ts
import { createClientMethod } from '@tkottke90/express-client';
import { z } from 'zod';

const userSchema = z.object({
  name: z.string(),
  email: z.string().email(),
});

export const createUser = createClientMethod(
  '/api/v1/user/',
  { method: 'GET', inputSchema: userSchema }
);
```

Here Zod provides a type definition for the input argument to the `createUser` method, so when we use it in the client code, we get type safety and autocompletion for the input data:

```typescript
// frontend/src/app.ts
import { createUser } from '<app-name>-client';

const userResponse: Response = await createUser({ name: 'John Doe', email: 'jon@example.com' });
```

Likewise if we try and pass in invalid data, we will get a runtime error that tells us exactly what is wrong with the input data:

```typescript
// frontend/src/app.ts
import { createUser } from '<app-name>-client';

const userResponse: Response = await createUser({ name: 'John Doe', phone: '123-456-7890' });
//                                                                   ^^^^^^^^^^^^^^^^^^^^
// Error: Invalid input data: Unrecognized key(s) in object: 'phone'
```

#### Output Validation

We can also make sure that the data we receive from the server is in the correct format by defining an output schema for the API endpoint.  We do this by passing in an Output Processor function that takes the raw response from the server and transforms it into the desired output format.  This allows us to handle the response on a per-endpoint basis, and we can use Zod to validate the response data as well.

```typescript
// backend/client/src/index.ts
import { createClientMethod } from '@tkottke90/express-client';
import { z } from 'zod';

const userResponseSchema = z.object({
  id: z.string(),
  name: z.string(),
  email: z.string().email(),
});

export const createUser = createClientMethod(
  '/api/v1/user/',
  { method: 'GET' },
  async (response) => {
    const data = await response.json();
    return userResponseSchema.parse(data);
  }
);
```

Now when we use the `createUser` method in the client code, we get type safety and autocompletion for the response data as well:

```typescript
// frontend/src/app.ts
import { createUser } from '<app-name>-client';

const userResponse = await createUser({ name: 'John Doe', email: 'jon@example.com' });
// userResponse is now typed as { id: string; name: string; email: string }
```

## Configuration

### Base URL Configuration

For different environments (development, staging, production), configure the base URL:

```typescript
// backend/client/src/config.ts
export const API_BASE_URL = process.env.VITE_API_URL || 'http://localhost:3000';

// backend/client/src/index.ts
import { createClientMethod } from '@tkottke90/express-client';
import { API_BASE_URL } from './config';

export const createUser = createClientMethod(
  `${API_BASE_URL}/api/v1/user/`,
  { method: 'POST' }
);
```

Then set the environment variable in your frontend:

```bash
# .env.production
VITE_API_URL=https://api.myapp.com
```

### Custom Fetch Options

Pass custom fetch options when calling client methods:

```typescript
import { createUser } from '<app-name>-client';

const userResponse = await createUser(
  { name: 'John Doe', email: 'jon@example.com' },
  {
    headers: {
      Authorization: `Bearer ${token}`,
    },
    credentials: 'include',
    signal: abortController.signal, // For request cancellation
  }
);
```

### Global Headers

Create a wrapper function for global configuration:

```typescript
// frontend/src/api/client.ts
import * as apiClient from '<app-name>-client';

const token = localStorage.getItem('authToken');

const defaultOptions: RequestInit = {
  headers: {
    Authorization: token ? `Bearer ${token}` : '',
  },
  credentials: 'include',
};

export const createUser = (data: Parameters<typeof apiClient.createUser>[0]) =>
  apiClient.createUser(data, defaultOptions);
```

## Error Handling

### Handling Validation Errors

When using Zod schemas, validation errors are thrown as `ZodError` instances:

```typescript
import { createUser } from '<app-name>-client';
import { z } from 'zod';

try {
  const user = await createUser({ name: 'John' }); // Missing required email
} catch (error) {
  if (error instanceof z.ZodError) {
    console.error('Validation failed:', error.errors);
    // [{ path: ['email'], message: 'Required' }]
    
    // Format for user display
    const messages = error.errors.map(e => `${e.path.join('.')}: ${e.message}`);
    alert(messages.join('\n'));
  }
}
```

### Handling HTTP Errors

Handle response errors based on status codes:

```typescript
import { createUser } from '<app-name>-client';

// Define with output processor that handles errors
export const createUser = createClientMethod(
  '/api/v1/user/',
  { method: 'POST', inputSchema: userSchema },
  async (response) => {
    if (!response.ok) {
      const error = await response.json().catch(() => ({ message: 'Unknown error' }));
      throw new Error(`HTTP ${response.status}: ${error.message}`);
    }
    const data = await response.json();
    return userResponseSchema.parse(data);
  }
);

// Usage with error handling
try {
  const user = await createUser({ name: 'John', email: 'john@example.com' });
} catch (error) {
  if (error.message.includes('HTTP 401')) {
    // Handle unauthorized
    redirectToLogin();
  } else if (error.message.includes('HTTP 409')) {
    // Handle conflict (e.g., user already exists)
    alert('User already exists');
  } else {
    // Handle other errors
    console.error('Failed to create user:', error);
  }
}
```

### Network Error Handling

```typescript
try {
  const user = await createUser({ name: 'John', email: 'john@example.com' });
} catch (error) {
  if (error instanceof TypeError && error.message === 'Failed to fetch') {
    alert('Network error. Please check your connection.');
  } else if (error.name === 'AbortError') {
    console.log('Request was cancelled');
  } else {
    throw error; // Re-throw unknown errors
  }
}
```

## Advanced Usage

### File Uploads

Handle file uploads with FormData:

```typescript
// backend/client/src/index.ts
export const uploadAvatar = createClientMethod(
  '/api/v1/user/avatar',
  { method: 'POST' }
);

// frontend/src/app.ts
const formData = new FormData();
formData.append('avatar', fileInput.files[0]);
formData.append('userId', '123');

const result = await uploadAvatar(formData, {
  // Don't set Content-Type - browser will set it with boundary
  headers: {
    Authorization: `Bearer ${token}`,
  },
});
```

### Request Cancellation

```typescript
const abortController = new AbortController();

try {
  const users = await listUsers({}, {
    signal: abortController.signal,
  });
} catch (error) {
  if (error.name === 'AbortError') {
    console.log('Request cancelled');
  }
}

// Cancel the request
setTimeout(() => abortController.abort(), 5000);
```

### Retry Logic

Implement retry logic for failed requests:

```typescript
// frontend/src/utils/retry.ts
export async function withRetry<T>(
  fn: () => Promise<T>,
  maxRetries = 3,
  delay = 1000
): Promise<T> {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await fn();
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await new Promise(resolve => setTimeout(resolve, delay * Math.pow(2, i)));
    }
  }
  throw new Error('Max retries exceeded');
}

// Usage
import { createUser } from '<app-name>-client';
import { withRetry } from './utils/retry';

const user = await withRetry(() => 
  createUser({ name: 'John', email: 'john@example.com' })
);
```

## Testing

### Mocking Client Methods

Using Vitest or Jest:

```typescript
// frontend/src/components/UserForm.test.ts
import { describe, it, expect, vi, beforeEach } from 'vitest';
import * as apiClient from '<app-name>-client';
import { UserForm } from './UserForm';

// Mock the entire module
vi.mock('<app-name>-client', () => ({
  createUser: vi.fn(),
  getUser: vi.fn(),
}));

describe('UserForm', () => {
  beforeEach(() => {
    vi.clearAllMocks();
  });

  it('should create user on submit', async () => {
    const mockUser = { id: '1', name: 'John', email: 'john@example.com' };
    vi.mocked(apiClient.createUser).mockResolvedValue(mockUser);

    const form = new UserForm();
    await form.submit({ name: 'John', email: 'john@example.com' });

    expect(apiClient.createUser).toHaveBeenCalledWith({
      name: 'John',
      email: 'john@example.com',
    });
  });

  it('should handle validation errors', async () => {
    const error = new Error('Validation failed');
    vi.mocked(apiClient.createUser).mockRejectedValue(error);

    const form = new UserForm();
    await expect(form.submit({ name: 'John' })).rejects.toThrow('Validation failed');
  });
});
```

## Troubleshooting

### Types Not Being Inferred

**Problem:** TypeScript doesn't recognize types from the client package.

**Solutions:**
1. Ensure `tsconfig.json` in the client has `"declaration": true`
2. Verify the build outputs `.d.ts` files in the `dist` directory
3. Check `package.json` has correct `"types"` field:
   ```json
   {
     "main": "./dist/index.js",
     "types": "./dist/index.d.ts"
   }
   ```
4. Restart TypeScript server in your editor: `Cmd+Shift+P` → "TypeScript: Restart TS Server"

### Build Fails After Code Changes

**Problem:** Client changes don't appear in frontend.

**Solutions:**
1. Rebuild the client:
   ```bash
   cd backend/client
   npm run build
   ```
2. Reinstall in frontend with force flag:
   ```bash
   cd frontend
   npm install file:../backend/client --force
   ```
3. Clear node_modules cache:
   ```bash
   rm -rf node_modules/.vite  # If using Vite
   ```

### "Module not found" Errors

**Problem:** Import errors when using the client package.

**Solutions:**
1. Verify the client is installed:
   ```bash
   npm list <app-name>-client
   ```
2. Check the package name in `backend/client/package.json` matches your import
3. Ensure `dist` directory exists and contains compiled files
4. Try reinstalling:
   ```bash
   npm uninstall <app-name>-client
   npm install file:../backend/client
   ```

### Zod Validation Errors in Production

**Problem:** Data validation fails unexpectedly in production.

**Solutions:**
1. Check that Zod schemas match backend validation
2. Log the actual data being sent/received:
   ```typescript
   const data = await response.json();
   console.log('Response data:', data);
   return schema.parse(data);
   ```
3. Use `.safeParse()` for better error handling:
   ```typescript
   const result = schema.safeParse(data);
   if (!result.success) {
     console.error('Validation errors:', result.error.errors);
     throw result.error;
   }
   return result.data;
   ```

### CORS Errors

**Problem:** Browser blocks requests with CORS errors.

**Solutions:**
1. Configure CORS in your Express backend:
   ```typescript
   import cors from 'cors';
   app.use(cors({
     origin: 'http://localhost:5173', // Your frontend URL
     credentials: true,
   }));
   ```
2. Use correct credentials option in client:
   ```typescript
   await createUser(data, { credentials: 'include' });
   ```

### Path Parameters Not Working

**Problem:** Path parameters like `:id` not being replaced.

**Solution:** Ensure you're passing the parameter in the data object:
```typescript
// ✅ Correct
await getUser({ id: '123' });

// ❌ Wrong
await getUser('123');
```

If the library doesn't automatically replace path parameters, you may need to implement this manually or check the library documentation for the correct syntax.

## API Reference

### createClientMethod

Creates a type-safe client method for calling API endpoints.

**Signature:**
```typescript
function createClientMethod<TInput, TOutput>(
  url: string,
  options?: {
    method?: 'GET' | 'POST' | 'PUT' | 'PATCH' | 'DELETE';
    inputSchema?: z.ZodSchema<TInput>;
  },
  outputProcessor?: (response: Response) => Promise<TOutput> | TOutput
): (data?: TInput, fetchOptions?: RequestInit) => Promise<TOutput>;
```

**Parameters:**
- `url` (string): The API endpoint URL. Can include path parameters like `/users/:id`
- `options` (object, optional):
  - `method`: HTTP method (default: 'GET')
  - `inputSchema`: Zod schema for input validation
- `outputProcessor` (function, optional): Function to process the response. Receives the raw Response object and should return the processed data

**Returns:**
A function that accepts:
- `data` (optional): Request data (body for POST/PUT/PATCH, path params for all methods)
- `fetchOptions` (optional): Additional fetch options (headers, credentials, etc.)

And returns a Promise resolving to the processed output.

**Examples:**

Basic usage:
```typescript
export const getUsers = createClientMethod('/api/v1/users', { method: 'GET' });
```

With input validation:
```typescript
export const createUser = createClientMethod(
  '/api/v1/users',
  { method: 'POST', inputSchema: z.object({ name: z.string(), email: z.string().email() }) }
);
```

With output processing:
```typescript
export const getUser = createClientMethod(
  '/api/v1/users/:id',
  { method: 'GET' },
  async (response) => {
    if (!response.ok) throw new Error('User not found');
    const data = await response.json();
    return userSchema.parse(data);
  }
);
```

Full example with all features:
```typescript
export const updateUser = createClientMethod(
  '/api/v1/users/:id',
  { 
    method: 'PATCH',
    inputSchema: z.object({
      id: z.string(),
      name: z.string().optional(),
      email: z.string().email().optional(),
    })
  },
  async (response) => {
    if (!response.ok) {
      const error = await response.json();
      throw new Error(error.message);
    }
    const data = await response.json();
    return userResponseSchema.parse(data);
  }
);
```
