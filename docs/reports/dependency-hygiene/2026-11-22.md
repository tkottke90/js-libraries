## Detection-failure investigation — `npm audit` 404 on bulk-advisories endpoint

- **Symptom:** `detect.mjs` exit 1 with `npm audit --json output has no
  vulnerabilities object — treating as a tooling failure`. Reproduced with a
  bare `npm audit --json` (exit 1): stdout is a bare JSON error object —
  `404 Not Found - POST
  https://npm.artifacts.tdkottke.com/-/npm/v1/security/advisories/bulk` —
  with stderr `npm error audit endpoint returned an error`.
- **What still works:** `npm outdated --json` through the same registry
  returns complete, current data; package fetch/metadata resolution works
  (the tree resolves and installs). Registry connectivity is fine (HTTP 200
  on `/-/ping`). The failure is isolated to the bulk security-advisories
  audit endpoint.
- **Diagnosis:** the configured registry is an Artifactory-style proxy
  (`server: openresty` response header) set via the gitignored `.npmrc`
  (`registry=https://npm.artifacts.tdkottke.com/`, npm 11.19.1). It answers
  `404` — not `401`/`403` — on
  `/-/npm/v1/security/advisories/bulk`, the endpoint `npm audit` uses to
  bulk-query advisories for the lockfile. A 404 from the proxy (rather than
  an auth error or a propagated upstream error) indicates the proxy does not
  implement or expose this endpoint, so `npm audit` cannot function against
  this registry no matter the credentials. `npm audit` worked in the
  2026-11-16 cohort report, so this is a change on the registry side since
  then.
- **Not treated as:** an npm-credentials problem (401/403 would look
  different; package fetch works), a lockfile problem (outdated works on the
  same tree), or a findings exit (npm's audit findings-exit convention is
  exit 1 *with* a `vulnerabilities` object; here the payload itself is an
  error object, which is what detect.mjs's contract correctly flags).
- **Classification per spec §12 preamble:** tooling failure — the detection
  script is working as documented; the infrastructure it depends on is not.
  No ad-hoc audit against a different registry was run to substitute
  results: that would improvise detection mechanics and could diverge from
  what every future script run sees.
- **Next step (for the user, outside this cohort):** re-enable or expose the
  `/-/npm/v1/security/advisories/bulk` endpoint on
  `npm.artifacts.tdkottke.com` (or point `.npmrc`'s `registry` at an
  endpoint-capable mirror). Until then, weekly security detection is
  structurally unavailable and reports can only cover drift.
- **Standing rule applied:** exit 1 was investigated and reported, never
  worked around.
